## 動作

- Ubuntu側がラズパイの `captures` を読み取り、新しいJPEGと同名JSONをセットで取り込みます。
- コピー元のデータは消しません。既存写真も、対応するJSONがある場合は対象です。
- JSONが完成し、JPEGと両方が3秒以上更新されていないものを対象にします。
- SHA-256とサイズで転送を確認し、JSON内の画像名も確認します。
- 同名・同内容の組は転送し直しません。同名で内容が違う場合は上書きせず「保留」と表示します。
- JSONを最後に公開します。途中で停止してJPEGだけが残っても、次回起動時に補完します。
- 通信途中の一時ファイルは `.import-` で始まる作業フォルダ内に置きます。強制終了で残る場合がありますが、次回は元から再取得するため転送済みとはみなしません。
- この方式はファイル単位で再取得します。大きなファイルの途中のバイト位置からの再開ではありません。

## 取り込みを１回試す

UbuntuのImageAnalysisフォルダで実行します。

```bash
python3 hardware/camera/import_captures.py
```

保存先は `data/raw/試行錯誤写真/` です。同じ名前で異なるファイルがすでにある場合は保留になります。

## 連続で取り込む

```bash
python3 hardware/camera/import_captures.py --watch
```

15秒ごとに確認し、未接続時は待って再試行します。Ubuntuとこのプログラムが動いている間だけ有効です。Ctrl+Cで停止します。PCを閉じたりWSLを停止した場合は取り込みも止まり、次の起動後に再実行が必要です。

失敗を繰り返す際は、画面の「接続・取得待ち」「保留」の内容を確認してください。初回の接続先未登録や鍵認証未設定は、待つだけでは解消しません。

## 接続後に確認すること

1. SSHの接続先が本当に対象のPiであること、鍵で無人ログインできること。
2. Piの `/home/morimoto.takumi.pi/captures/` が正しいこと。
3. １組取り込み後、同名JPEGとJSONがUbuntu側にあること。
4. 再実行で重複転送しないこと。
5. 撮影アプリで新しく撮り、連続取り込み中にUbuntuへ届くこと。
6. 接続切断・復帰後に未取得分を取り込めること。
